# SPEC — アークナイツ 公開求人「上級資格証」クイズ

> このファイルが「何を作るか」の唯一の情報源です。
> AI はここに書かれていないものを作りません。逆に、ここに書けば作ります。

## 目的

アークナイツ（Hypergryph）の「公開求人」で、星4以上が確定で出るタグの組み合わせ（以下 **確定枠**）を見逃さないための練習クイズ。

5つの求人タグを提示し、その中から確定枠となる組み合わせを選ぶ（または「確定枠なし」と答える）。正誤を即座に判定し、繰り返し反復して判断力を鍛える。

## 対象ユーザー

アークナイツのプレイヤー本人。ゲームの基本用語（タグ名、レアリティ）は既知である前提で、用語の解説は不要。

## 用語とドメインルール

この節は実装の根拠になる。**曖昧さを残さないこと。**

### タグの種類

| 分類 | タグ                                                                                                                                |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 資格 | 上級エリート / エリート / ロボット                                                                                                  |
| 職業 | 先鋒 / 前衛 / 重装 / 狙撃 / 術師 / 医療 / 補助 / 特殊                                                                               |
| 位置 | 近距離 / 遠距離                                                                                                                     |
| 特性 | 初期 / 火力 / 生存 / 防御 / 治療 / 支援 / 範囲攻撃 / 減速 / 牽制 / 弱化 / 強制移動 / 爆発力 / 召喚 / 高速再配置 / コスト回復 / 元素 |

### 確定枠とは

タグの組み合わせ（1〜3個）のうち、**それを選ぶと星4以上のオペレーターが確定で出るもの**。

このアプリは全オペレーターのタグ情報を持たない。代わりに、**確定枠そのものをデータとして持つ**（確定枠テーブル）。判定はこのテーブルへの照会で行う。

この方式を採る理由:

- オペレーターのタグ情報から確定枠を計算する方式は、**星3以下のデータが1件でも欠けると、確定枠でない組み合わせを確定枠と誤判定する**。データ不足が「偽の確定枠」として表面化し、クイズが誤答を教えることになる
- 確定枠テーブル方式なら、データ不足は「確定枠の見落とし」として現れる。さらに各行が人間の目で正誤を判断できる形なので、レビューが成立する

### 確定枠テーブルの表現

テーブルは **最小の組み合わせのみ** を保持する。

例: `{重装, 狙撃}` が確定枠なら、それだけを1行として持つ。`{重装, 狙撃, 火力}` は行として持たない。

理由: タグを追加すると対象オペレーターは絞られる（AND 条件）ため、最低レアリティは下がらない。よって最小の組み合わせを含むものは全て確定枠である。

各行が持つもの:

- タグの組み合わせ（1〜3個）
- 最低レアリティ（4 / 5 / 6）
- そのタグ組み合わせで出る対象オペレーター名の一覧

### 判定ルール

選択タグ集合 S（1〜3個）が確定枠である ⟺ **テーブルに、タグ集合が S の部分集合となる行が存在する**。

例: テーブルに `{重装, 狙撃}` がある場合、

- S = `{重装, 狙撃}` → 確定枠（完全一致）
- S = `{重装, 狙撃, 火力}` → 確定枠（`{重装, 狙撃}` を部分集合として含む）
- S = `{重装}` → テーブルに `{重装}` 単体の行が無ければ確定枠ではない

### 出題タグプールと網羅性

**このアプリの正しさは、テーブルの網羅性に依存する。** テーブルに行が欠けていると「本当は確定枠があるのに『なし』が正解」と教えることになり、アプリの目的そのものを損なう。

そのため、出題に使うタグを **出題タグプール** として明示的に定義し、次の不変条件を置く。

> **不変条件: 出題タグプール内のタグから作れる 1〜3 個の全組み合わせについて、確定枠であるものが漏れなくテーブルに存在する。**

この不変条件は人間が保証する（機械的には検証できない）。プールは検証済みの範囲だけを含み、テーブルの検証が進むにつれて広げる。

実装はプール外のタグを出題してはならない。

### 確定枠テーブルの検証に必要な前提知識

人間がテーブルの行を検証するときに使う、ゲーム側のルール。

- 星6は `上級エリート` タグを選んだときのみ出現する
- ロボットは `ロボット` タグを選んだときのみ出現する
- したがって `{上級エリート}` は単体で星6確定、`{エリート}` は単体で星5確定であり、どちらも確定枠である

## 機能

### F-1 タグ定義と出題タグプール

受け入れ条件:

- `src/data/tags.ts` にタグが分類（資格 / 職業 / 位置 / 特性）付きで定義され、総数が 29 個である
- `Tag` 型がタグ名のユニオン型で、定義外の文字列を代入すると型エラーになる
- 出題タグプールが、タグ全体とは別の配列として定義されている
- 出題タグプールの全要素が、定義済みタグに含まれる

### F-2 確定枠テーブル

受け入れ条件:

- `src/data/guaranteed.ts` に確定枠テーブルが定義されている
- 各行が `{ タグ配列(1〜3個), 最低レアリティ(4|5|6), 対象オペレーター名の配列 }` を持つ
- 全ての行のタグが、出題タグプールに含まれる
- **テーブルに、他の行の部分集合となる冗長な行が存在しない**（最小性）
- ファイル先頭に、データの出典・検証状況・不変条件（出題タグプール内は網羅されていること）を記したコメントがある
- `{上級エリート}` と `{エリート}` の行が存在する
- 行数は 10 行以上

### F-3 確定枠の判定

受け入れ条件:

- タグ集合とテーブルを渡すと `{ isGuaranteed, matchedEntries }` を返す
- 完全一致する行があれば確定枠と判定される
- 選択タグが行のタグを**部分集合として含む**場合も確定枠と判定される（`{重装,狙撃,火力}` に対し `{重装,狙撃}` の行）
- 部分集合になる行が無ければ確定枠ではないと判定される
- タグを 4 個以上渡すと例外を投げる
- タグを 0 個渡すと例外を投げる
- 検証は**テスト用の固定テーブル**に対して行う（実データを差し替えてもテストが壊れないようにするため）

### F-4 5タグからの確定枠の全列挙

受け入れ条件:

- 提示された5タグに対し、タグ集合がその5タグの部分集合となる行を全て返す
- 該当する行が無い5タグに対しては空配列を返す
- 結果はタグ数の少ない順に並ぶ

### F-5 出題の生成

**テーブルからの逆引き方式**で生成する。棄却サンプリング（生成→判定→やり直し）は使わない。

受け入れ条件:

- 生成される5タグは重複せず、全て出題タグプールに含まれる
- 「確定枠あり」を要求すると、テーブルから1行選び、そのタグを含む形で5タグが構成される
- 「確定枠なし」を要求すると、確定枠を1つも含まない5タグが返る
- 確定枠あり / なし がおよそ半々（50%）の比率で出題される
- `上級エリート` `エリート` は他のタグより低い確率で出現する
- 同じシードなら常に同じ問題が生成される

### F-6 出題画面

受け入れ条件:

- 5つのタグがボタンとして表示される
- タグをクリックすると選択状態になり、もう一度クリックすると解除される
- 選択できるタグは最大3つ。3つ選択済みの状態で4つ目をクリックしても選択されない
- 「確定枠なし」ボタンが常に表示される
- タグを1つも選んでいない状態では「回答する」ボタンが押せない

### F-7 正誤判定と結果表示

受け入れ条件:

- タグを選んで回答したとき、その組み合わせが確定枠なら **正解** と表示される
- 確定枠が複数ある場合、**そのうちどれか1つを満たしていれば正解**とする
- 「確定枠なし」を選び、実際に確定枠が存在しなければ正解と表示される
- 「確定枠なし」を選んだが確定枠が存在した場合は不正解と表示される
- 正解・不正解にかかわらず、結果画面にその問題の**確定枠を全て**表示する
- 各確定枠について、タグの組み合わせ・最低レアリティ・対象オペレーター名が表示される
- 確定枠が無い問題では、確定枠が無い旨が表示される
- 「次の問題へ」で新しい問題が出題され、選択状態と結果表示がリセットされる

### F-8 スコア

受け入れ条件:

- 連続正解数が表示される。正解で 1 増え、不正解で 0 に戻る
- 正答率（正解数 / 回答数）が表示される
- 未回答時に正答率表示が壊れない（0 除算しない）
- スコアは localStorage に保存され、リロード後も保持される
- localStorage が空、または壊れた値のとき、初期値で起動しクラッシュしない
- スコアをリセットするボタンがあり、押すと連続正解数と正答率が 0 になる

## 非目標（スコープ外）

- ユーザー認証、サーバーサイド、外部 API 通信は**作らない**
- **全オペレーターのタグデータベースは持たない**（確定枠テーブルのみを持つ）
- 任意のタグ組み合わせに対する排出オペレーター検索機能は**作らない**（確定枠に載っている組み合わせのみ表示する）
- 確定枠テーブルを自動生成・自動更新する仕組みは**作らない**（人間が保守する）
- 星5確定・星6確定を星4確定と区別した専用の出題モードは**作らない**（結果画面に最低レアリティを出すので十分）
- 間違えた問題の復習機能は**作らない**
- 多言語対応は**しない**（日本語のみ）
- 実際の公開求人の排出確率シミュレーションは**しない**
- タグの絞り込み時間（9時間 / 3時間50分など）の話は**扱わない**

## 技術制約

- Vite + React + TypeScript（変更しない）
- 状態管理ライブラリは追加しない（React の標準機能で作る）
- 永続化は localStorage のみ
- **依存パッケージを追加しない**（判定ロジックも組み合わせ生成も乱数も自前で書く）
- タグ定義・出題タグプール・確定枠テーブルは `src/data/` 配下の TypeScript ファイルに置く
- 判定ロジックは UI から独立した純粋関数として実装し、Vitest で直接テストできるようにする
- ロジックのテストは**テスト用の固定テーブル**に対して書く。実データ（`src/data/`）に依存させない

## 画面

単一画面（ルーティングなし）。

- `/` — クイズ画面。出題・解答・結果表示・スコアを1画面に収める

## データの正確性について

確定枠テーブルと出題タグプールの正しさは、**人間が保証する**。

- AI が初期データを作成してよいが、それは**未検証の暫定値**である
- AI はデータの正しさを「確認した」「検証した」と主張してはならない
- テーブルの網羅性（出題タグプール内に漏れが無いこと）は機械的に検証できない。人間のレビューが唯一の担保である
- データの誤りが見つかった場合、修正は `src/data/` 配下のみで完結する。ロジックとテストには波及しない

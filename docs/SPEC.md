# SPEC — アークナイツ 公開求人「上級資格証」クイズ

> このファイルが「何を作るか」の唯一の情報源です。
> AI はここに書かれていないものを作りません。逆に、ここに書けば作ります。

## 目的

アークナイツ（Hypergryph）の「公開求人」で、星4以上が確定で出るタグの組み合わせ（以下 **確定枠**）を見逃さないための練習クイズ。

5つの求人タグを提示し、その中から確定枠となる組み合わせを選ぶ（または「確定枠なし」と答える）。正誤を即座に判定し、繰り返し反復して判断力を鍛える。

## 対象ユーザー

アークナイツのプレイヤー本人。ゲームの基本用語（タグ名、レアリティ）は既知である前提で、用語の解説は不要。

## 用語とドメインルール

この節は実装の根拠になる。**曖昧さを残さないこと。**

### タグの種類

| 分類 | タグ                                                                                                                                |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 資格 | 上級エリート / エリート / ロボット                                                                                                  |
| 職業 | 先鋒 / 前衛 / 重装 / 狙撃 / 術師 / 医療 / 補助 / 特殊                                                                               |
| 位置 | 近距離 / 遠距離                                                                                                                     |
| 特性 | 初期 / 火力 / 生存 / 防御 / 治療 / 支援 / 範囲攻撃 / 減速 / 牽制 / 弱化 / 強制移動 / 爆発力 / 召喚 / 高速再配置 / コスト回復 / 元素 |

**注意: 上表のタグ一覧および後述のオペレーターデータは AI が作成した暫定値であり、未検証。** 実装はタグ一覧をハードコードせず、データファイル1箇所から読むこと（後で人間が修正できるようにするため）。

### タグとオペレーターの対応

- `上級エリート` は レアリティ6 のオペレーターに一致する
- `エリート` は レアリティ5 のオペレーターに一致する
- `ロボット` はデータ上 `ロボット` タグを持つオペレーターに一致する
- それ以外のタグは、オペレーターが持つタグ配列との一致で判定する

### 母集団の除外ルール

選択タグ集合 S に対して、判定の母集団 P は全オペレーターから以下を除外して作る。

- `上級エリート` ∉ S のとき、**レアリティ6を除外する**（星6は上級エリートタグ選択時のみ出現するため）
- `ロボット` ∉ S のとき、**ロボットを除外する**

### 確定枠の定義

選択タグ集合 S（1〜3個、提示された5タグの部分集合）について:

1. 上記ルールで母集団 P を作る
2. P のうち **S の全タグを満たす**（AND 条件）オペレーター集合を M とする
3. **M が空でなく、かつ M の最低レアリティが 4 以上** ならば、S は確定枠である

M が空の組み合わせは確定枠ではない。

## 機能

### F-1 オペレーターデータ

判定の基礎となるデータをリポジトリ内に持つ。

受け入れ条件:

- オペレーターは `{ 名前, レアリティ(1〜6), タグ配列 }` の形で表現される
- タグの正式一覧がデータとして定義され、実装コードにタグ名を直接書かない
- データファイル先頭に「AI 作成の暫定データであり未検証」である旨のコメントがある
- データ件数は 20 件以上（プロトタイプとして判定が成立する最小規模）
- レアリティ 3 以下のオペレーターが含まれる（含まれないと「確定枠でない」判定が成立しないため）

### F-2 確定枠の判定

上記「確定枠の定義」を実装する。

受け入れ条件:

- タグ集合を渡すと、確定枠かどうか / 一致オペレーター一覧 / 最低レアリティ を返す
- `上級エリート` を含まない組み合わせの結果に、レアリティ6のオペレーターが含まれない
- `ロボット` を含まない組み合わせの結果に、ロボットが含まれない
- 一致オペレーターが 0 件の組み合わせは、確定枠ではないと判定される
- タグを 4 個以上渡した場合はエラーになる

### F-3 5タグからの確定枠の全列挙

提示された5タグから、確定枠となる組み合わせを全て求める。

受け入れ条件:

- 5タグの 1〜3 個の組み合わせ（計 25 通り）を全て評価する
- 確定枠が存在しない5タグに対しては、空の結果を返す
- 結果は確定枠のタグ数が少ない順に並ぶ

### F-4 出題の生成

5つのタグを抽選して問題を作る。

受け入れ条件:

- 5つのタグは重複しない
- 確定枠が存在する問題と存在しない問題が、およそ半々（50%）の比率で出題される
- `上級エリート` と `エリート` は、他のタグより低い確率で出現する
- **生成が指定回数（例: 100 回）試行しても目標の条件を満たせない場合、最後に生成した問題を返して無限ループしない**
- 乱数の種を外部から与えられ、同じ種なら同じ問題が生成される（テスト可能にするため）

### F-5 出題画面

受け入れ条件:

- 5つのタグがボタンとして表示される
- タグをクリックすると選択状態になり、もう一度クリックすると解除される
- 選択できるタグは最大3つ。3つ選択済みの状態で4つ目をクリックしても選択されない
- 「確定枠なし」ボタンが常に表示される
- タグを1つも選んでいない状態では「回答する」ボタンが押せない

### F-6 正誤判定と結果表示

受け入れ条件:

- タグを選んで回答したとき、その組み合わせが確定枠なら **正解** と表示される
- 確定枠が複数ある場合、**そのうちどれか1つを選んでいれば正解**とする
- 「確定枠なし」を選び、実際に確定枠が存在しなければ正解と表示される
- 「確定枠なし」を選んだが確定枠が存在した場合は不正解と表示される
- 正解・不正解にかかわらず、結果画面にその問題の**確定枠を全て**表示する
- 各確定枠について、タグの組み合わせ・最低レアリティ・一致オペレーター名が表示される
- 「次の問題へ」で新しい問題が出題され、選択状態がリセットされる

### F-7 スコア

受け入れ条件:

- 連続正解数が表示される。正解で 1 増え、不正解で 0 に戻る
- 正答率（正解数 / 回答数）が表示される
- スコアは localStorage に保存され、リロード後も保持される
- スコアをリセットするボタンがあり、押すと連続正解数と正答率が 0 になる

## 非目標（スコープ外）

- ユーザー認証、サーバーサイド、外部 API 通信は**作らない**
- 実際のゲームの全オペレーターの網羅は、プロトタイプ段階では**目指さない**（F-1 の 20 件以上で足りる）
- 星5確定・星6確定を星4確定と区別した専用の出題モードは**作らない**（結果画面に最低レアリティを出すので十分）
- 間違えた問題の復習機能は**作らない**
- 多言語対応は**しない**（日本語のみ）
- 実際の公開求人の排出確率シミュレーションは**しない**
- タグの絞り込み時間（9時間 / 3時間50分など）の話は**扱わない**

## 技術制約

- Vite + React + TypeScript（変更しない）
- 状態管理ライブラリは追加しない（React の標準機能で作る）
- 永続化は localStorage のみ
- **依存パッケージを追加しない**（判定ロジックも組み合わせ生成も自前で書く）
- オペレーターデータとタグ定義は `src/data/` 配下の TypeScript ファイルに置く
- 判定ロジックは UI から独立した純粋関数として実装し、Vitest で直接テストできるようにする

## 画面

単一画面（ルーティングなし）。

- `/` — クイズ画面。出題・解答・結果表示・スコアを1画面に収める

## データの正確性について

F-1 のオペレーターデータは AI が作成した**未検証の暫定値**である。ゲームの実データと食い違う可能性が高い。

したがって:

- ロジックのテストは、実データ依存ではなく**テスト用の固定データ**に対して書くこと（実データを差し替えてもテストが壊れないようにするため）
- 実データの正確性の検証は人間が行う。AI はデータの正しさを「確認した」と主張しないこと

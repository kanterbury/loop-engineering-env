description: ループの進捗を要約して報告する（backlog の消化率、直近の履歴、現在の状態）
---

ループの現状を人間向けに要約する。**読むだけ。実装もコミットもしない。**

## 集める情報

1. `.loop/state.md` — 現在のタスク / 直前の verify / 次の一手 / 連続失敗回数
2. `.loop/backlog.md` — チェック済み（`- [x]`）の件数 / 未チェック（`- [ ]`）の件数
3. `.loop/journal.md` — 直近5件
4. `git log --oneline -10` — 直近のコミット

## 報告フォーマット

```
進捗: 7/15 完了 (47%)
現在: T-008 削除ボタンの実装 / 直前の verify: PASS
直近: T-005 PASS → T-006 PASS → T-007 FAIL(lint) → T-007 PASS

気になる点:
- （FAIL が続いている / 同じタスクで手戻りしている / backlog が枯渇しそう、等があれば）
```

## 注意して見るもの

以下に該当したら、単なる進捗ではなく **問題として明示的に指摘する**。自走ループは静かに壊れるので、ここが人間の唯一の気づきポイントになる。

- journal に同じタスク ID の FAIL が3回以上出ている → 実装が詰まっている
- `- [x]` なのに journal に PASS の記録が無い → **赤のままコミットされた疑い**
- 完了タスクから受け入れ条件が消えている → **完了の根拠が失われている**（消さずに残す規約）
- テストファイルの削除・skip がコミットに含まれている → **テストを緩めて通した疑い**
- SPEC に無い機能のタスクが `- [x]` になっている → スコープが膨張している

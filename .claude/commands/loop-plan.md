`docs/SPEC.md` を作業単位に分解し、`.loop/backlog.md` の Todo を作る。

## 手順

1. `docs/SPEC.md` を読む。テンプレートのまま未記入なら、**分解せずに停止して、仕様を書くよう促す**
2. `.loop/backlog.md` を読み、既存の Done / In Progress を確認する（**既存タスクを消さない**）
3. SPEC の各機能を、下記の粒度基準でタスクに分解する
4. Todo セクションに追記する。既に Done のものは重複させない

## 粒度の基準

**1タスク = 1周回 = 1コミットで終わること。** これが崩れると、周回の途中で終わって状態ファイルが実態とズレる。

- ✅ 良い例: 「Todo 型の定義と空一覧の表示」「入力欄からタスクを追加できる」「localStorage への保存」
- ❌ 粗すぎ: 「Todo アプリを作る」「CRUD を実装する」
- ❌ 細かすぎ: 「変数名を todos にする」「import 文を追加する」

目安は「1コンポーネント」または「1機能の1つの振る舞い」。

依存順に並べる（型定義 → 表示 → 操作 → 永続化 → 仕上げ）。先頭から順に消化しても破綻しない順序にすること。

## 各タスクに必ず書くもの

```markdown
- [ ] T-003 タスクを完了/未完了にトグルできる
  - 受け入れ条件: チェックボックスをクリックすると、その行に打ち消し線が付く
  - 検証: Vitest (src/TodoItem.test.tsx) + E2E (e2e/todo.spec.ts)
```

- **ID** — `T-001` から連番。既存の最大値の次から振る
- **受け入れ条件** — テストにそのまま翻訳できる形。「〜が表示される」「〜をクリックすると〜になる」
- **検証** — どのテストで確認するか

受け入れ条件が書けないタスクは、**分解が足りないか SPEC が曖昧**。SPEC が曖昧な場合は推測で埋めず、何が不明かを報告する。

## 報告

生成したタスク数と、最初の3件のタイトルだけを報告する。全件を出力しない。

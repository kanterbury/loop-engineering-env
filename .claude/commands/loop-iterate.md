---
description: ループを1周回す（タスクを1つ実装 → verify → コミット → 状態更新）
---

ループの1周回を実行する。`/loop /loop-iterate` から繰り返し呼ばれる前提で書かれている。

## 手順

### 1. 現在地を読む

`.loop/state.md` と `.loop/backlog.md` を読む。**自分の記憶ではなくファイルを信頼すること**（コンテキストが圧縮されている可能性がある）。

停止条件に該当していないか先に確認する:

- backlog に未チェック（`- [ ]`）のタスクが無い → **停止して報告**
- state.md の連続失敗回数が 3 以上 → **停止して報告**
- `docs/SPEC.md` が未記入（テンプレートのまま） → **停止して、SPEC を書くよう促す**

### 2. タスクを1つ選ぶ

未チェックのタスクを上から **1つだけ** 選ぶ。依存関係があるなら先に必要なものを選んでよいが、**同時に2つ着手しない**。

**backlog 上でタスクを移動させない。** 着手中であることは `.loop/state.md` の「現在のタスク」に書く。backlog 側に進行中セクションを作ると、state.md と二重管理になって必ず食い違う。

### 3. 実装する

- SPEC の受け入れ条件を満たす実装 + それを検証するテストを書く
- 途中で `npm run verify:quick` を何度回してもよい
- **SPEC に無い機能は追加しない**

### 4. 検証する

`npm run verify` を実行する。

- **赤なら** → 原因を直して再実行。3回連続で失敗したら journal に失敗内容と試したことを書いて **停止して報告**
- **緑なら** → 次へ

UI を変更した周回では、`.loop/screenshots/home.png`（および該当画面の PNG）を **Read ツールで画像として開いて目視確認する**。テストが緑でもレイアウトは壊れうる。崩れていたら直して 4 をやり直す。

### 5. 記録する

verify が緑のときだけ実行する。**赤のままコミットしない。**

1. `git add` → `git commit -m "T-XXX タスク名"`
2. `.loop/backlog.md`: 該当タスクを **その場で** `- [ ]` → `- [x]` にし、行末に commit hash を付ける。
   **受け入れ条件は消さない。** 何を根拠に完了としたかが後から読んで分かるようにするため。
   仕様外の判断をした場合は `- 結果:` 行を足して残す
3. `.loop/state.md`: 3項目を上書き、連続失敗回数を 0 に
4. `.loop/journal.md`: 1行追記（`- YYYY-MM-DD iter-NN / T-XXX / verify: PASS / commit <hash> / 変更ファイル`）

状態ファイルの更新は次のコミットに含めてよい（毎回2コミットにしない）。

## 報告

**1〜3行で終えること。** 長文はコンテキストを食い潰し、自走できる周回数を減らす。詳細は journal.md に書けばよい。

形式:

```
T-003 完了トグルを実装 / verify: PASS / 次: T-004 削除機能
```

停止した場合のみ、理由と必要な判断を具体的に書く。
